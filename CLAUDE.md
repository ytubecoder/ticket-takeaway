# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

Ticket Takeaway is a markdown-native project board system. It reads `PRODUCT_BACKLOG.md` and `PRODUCT_SPECIFICATION.md` files and renders them as an interactive HTML kanban dashboard. No database, no JSON intermediary — the markdown files ARE the board.

## Key Commands

```bash
# Generate the dashboard (opens in browser)
python3 ~/.claude/ticket-takeaway/generate.py

# Or via Claude Code skill
/dashboard

# Move a ticket between sections
/dashboard status ticket-takeaway B-01 for-review

# Accept a feature (moves to PRODUCT_SPECIFICATION.md)
/accept ticket-takeaway B-01

# Add a new ticket
/dashboard add ticket-takeaway "New feature title"

# JSON output (for programmatic agent queries)
python3 ~/.claude/ticket-takeaway/generate.py --json
```

## Architecture

```
PRODUCT_BACKLOG.md  ──┐
                      ├──→  src/generate.py  ──→  docs/sdlc-dashboard.html
PRODUCT_SPECIFICATION.md ─┘
```

**`src/generate.py`** (~1200 lines, Python 3.10+, no external deps) is the core of the project. It:
1. Reads `~/.claude/ticket-takeaway/registry.json` for project paths
2. Parses `PRODUCT_BACKLOG.md` — `##` headings = sections/columns, `###` headings = tickets
3. Parses `PRODUCT_SPECIFICATION.md` for accepted features
4. Collects git/code stats via shell commands
5. Renders a self-contained HTML file with inline CSS/JS (dark theme kanban)

Data model: `Ticket` dataclass (id, title, priority, complexity, status, section, column, description, acceptance_criteria, parent, rationale, depends, summary, archived) → `Project` dataclass (tickets + CodeStats) → HTML or JSON.

**`src/skills/`** contains Claude Code skill definitions:
- `dashboard/SKILL.md` — the `/dashboard` skill
- `review/SKILL.md` — the `/review` skill for acceptance workflow

Source files in `src/` are canonical. They deploy to `~/.claude/` for runtime use (see `INSTALL.md` for the deployment map).

## Ticket Format in PRODUCT_BACKLOG.md

```markdown
### {ID}: {Title}
Priority: {priority} | Complexity: {complexity} | Status: {status}
Parent: {parent-id}       (optional — for sub-tickets)
Rationale: {reason}       (optional — captures "why" decisions)
Depends: {id1}, {id2}     (optional — inter-ticket dependencies)
{Description}
- [ ] Acceptance criterion
- [x] Completed criterion
```

ID prefixes: `B-` (backlog), `R-` (released), `I-` (idea), `W-` (won't do), `Z-` (icebox), `BUG-` (bug).

Sections (`## WIP`, `## Backlog`, `## Ideas`, etc.) map directly to dashboard columns. Moving a ticket = cutting the `###` block and pasting it under a different `##` heading.

## Product Backlog Rules

`PRODUCT_BACKLOG.md` is the single source of truth for all active feature work. The dashboard reads directly from this file.

**Closed-loop workflow — every feature status change must update PRODUCT_BACKLOG.md:**

1. **Starting work:** Move item to `## WIP`, set `Status: in-progress`
2. **Blocked:** Update to `Status: blocked` (stays in `## WIP`)
3. **Code complete:** Move to `## For Review`, set `Status: for-review`
4. **Accepted:** Run `/accept {project} {ID}`
5. **New idea:** Add to `## Ideas` or `## Backlog`
